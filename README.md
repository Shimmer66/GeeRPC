#### RPC定义

RPC（远程过程调用）是一种协议，允许程序在不同计算机上进行调用，就像在同一台计算机上调用本地方法一样。通过 RPC，调用方（客户端）发出请求，调用在另一台计算机上（服务端）执行，然后将结果返回给调用方。RPC 协议隐藏了网络通信的复杂性，使开发者无需关心底层的网络传输、序列化和反序列化等细节，只需专注于业务逻辑的实现。常见的RPC框架有gRPC、Thrift。

##### 具体实现原理
- 组件
    - 客户端：发起RPC调用的程序或进程。客户端通常有一个存根（Stub），它是一个代理对象，用于代表客户端调用远程的实际服务。
    - 服务器：接收RPC调用并执行实际逻辑的程序或进程。服务器也有一个存根，用于处理来自客户端的调用请求。
    - 通信协议：用于在客户端和服务器之间传输数据的协议。常见的协议有TCP/IP、HTTP等。
    - 编码/解码：将数据从编程语言的本地格式转换为可以通过网络传输的格式（编码），以及将网络传输的格式转换回本地格式（解码）。常见的序列化格式有 Protocol Buffers、JSON 和 XML 等。
- 调用流程
    - 客户端调用：客户端调用本地存根，发起调用请求。
    - 请求传输：客户端存根将调用请求编码为网络传输格式，并通过通信协议将其发送到服务器。
    - 请求接收与解码：服务器接收到请求后，将请求信息解码成可理解的格式。
    - 方法执行：服务器的存根调用实际的服务实现，执行请求的方法。
    - 结果编码与传输：服务实现返回结果后，服务器的存根将结果编码成网络传输格式，并通过通信协议将其发送回客户端。
    - 结果接收与解码：客户端存根接收到结果后，将其解码成本地格式，并返回给发起调用的程序。
##### 优点
- 高性能：RPC 使用二进制数据传输而不是 JSON，这显著减少了数据量，提高了传输效率。相比于 RESTful 协议，RPC 的解析开销更小，适合高并发和低延迟的场景。高性能：RPC 使用二进制数据传输，减少了数据量，提高了传输效率，适合高并发和低延迟的场景。
- 简化开发：通过自动生成的客户端和服务器代码，开发者可以像调用本地函数一样调用远程服务。这种自动化降低了手工编码的复杂性，简化了开发过程。强类型：RPC 框架通常支持强类型定义，减少了数据解析的错误，提高了代码的健壮性。
- 灵活性：RPC 支持多种传输协议，如 TCP 和 HTTP/2，开发者可以根据具体需求选择合适的传输层，从而提升系统的适应性。

##### 应用场景
- 微服务架构：在微服务架构中，服务之间需要频繁通信，RPC 可以提供高效的服务调用机制，适合高并发的场景。
- 分布式系统：在分布式系统中，节点之间需要进行远程方法调用，RPC 可以隐藏网络通信的复杂性，简化开发。
- 实时系统：在对延迟敏感的实时系统中，RPC 的高效传输机制可以显著降低通信延迟，提升系统性能。

#### 功能

  - [x] 服务端与客户端
  - [x] 注册中心与服务发现： 注册中心允许服务端动态注册和注销服务。服务端定期向注册中心发送心跳，保证当前服务可用。注册中心维护一个可用服务列表，并将列表提供给客户端和其他服务端。客户端通过注册中心获取最新的服务端列表，并通过服务发现机制选择当前可用的服务端进行请求。
  - [x] 负载均衡： 多个客户端的请求不能全部发送到一台服务端，应该均衡地选择全部的服务端，避免单个服务端过载。使用了 Random 和 RoundRobin算法
  - [x] 超时处理： 包括连接超时，读写超时，服务端处理报文超时。支持客户端设置请求超时时间，如果指定时间内未得到响应，则返回超时错误。
  - [x] HTTP支持： 支持 RPC 和 HTTP 协议的转换功能。允许客户端通过 HTTP 方式发送 RPC 请求，服务端将 HTTP 请求转换为 RPC 请求进行处理，并将响应转换为 HTTP 响应返回给客户端。
